# NVM2App 개발환경 구성 가이드

새 PC에서 아무것도 기억나지 않는 상태로도 이 문서만 순서대로 따라 하면
개발환경 구성 → 앱 실행까지 완료되도록 작성되었다.

---

## 0. 사전 준비물

| 항목 | 내용 |
|---|---|
| OS | Windows 10/11 |
| Python | **3.12.x** (개발 당시 3.12.9 사용) — https://www.python.org/downloads/ 에서 설치. 설치 시 **"Add python.exe to PATH" 체크 필수** |
| 프로젝트 소스 | git 저장소에서 clone 하거나, 과거 빌드 결과물의 `source` 폴더(스냅샷)를 통째로 복사 |

프로젝트 루트 폴더 기준으로 아래 파일들이 보여야 정상이다:
`main.py`, `build.bat`, `ftd2xx.dll`, `resources.qrc`, `b_core/`, `c_ui/`, `2_resource/`

> **ftd2xx.dll 이 없으면** 펌웨어 업데이트 기능이 동작하지 않는다.
> 이 DLL 은 저장소에 포함되어 있으므로 clone 하면 루트에 존재해야 한다.

---

## 1. 가상환경 생성

프로젝트 루트 폴더에서 터미널을 열고 실행한다.
(폴더명은 반드시 `.venv` — build.bat 이 이 이름을 참조한다)

```cmd
py -3.12 -m venv .venv
```

> `py` 명령이 없다면: `python -m venv .venv`
> (이때 `python --version` 이 3.12.x 인지 먼저 확인할 것)

## 2. 가상환경 활성화

**명령 프롬프트(CMD):**
```cmd
.venv\Scripts\activate.bat
```

**PowerShell:**
```powershell
.venv\Scripts\Activate.ps1
```

> 활성화되면 프롬프트 앞에 `(.venv)` 가 표시된다.
> PowerShell 에서 "스크립트 실행이 비활성화" 오류가 나면 관리자 PowerShell 에서
> `Set-ExecutionPolicy RemoteSigned` 실행 후 다시 시도한다.

## 3. pip 업데이트

```cmd
python -m pip install --upgrade pip
```

## 4. 패키지 설치

### 방법 A — 버전 고정 설치 (표준)

```cmd
pip install PySide6==6.10.2
pip install pyqtgraph==0.14.0
pip install pyserial==3.5
pip install pyqtdarktheme-fork==2.3.4
pip install pydantic
pip install ftd2xx
pip install pyinstaller
```

| 패키지 | 용도 |
|---|---|
| PySide6 | Qt GUI 프레임워크 |
| pyqtgraph | 실시간 차트 |
| pyserial | 시리얼(COM) 통신 |
| pyqtdarktheme-fork | 전역 라이트 테마 |
| pydantic | param 스키마 검증 |
| ftd2xx | FTDI 장치 제어 (펌웨어 업데이트) |
| pyinstaller | 배포용 exe 빌드 (빌드 시에만 사용) |

### 방법 B — 과거 빌드 스냅샷에서 복원할 경우

빌드 결과물의 `source` 폴더에는 그 시점의 전체 패키지 목록이
`requirements_snapshot.txt` 로 저장되어 있다. 그대로 복원하려면:

```cmd
pip install -r requirements_snapshot.txt
```

## 5. Qt 리소스 파일 컴파일

폰트/아이콘 등 리소스(`resources.qrc`)를 파이썬 모듈로 변환한다.
**clone 직후에는 `resources_rc.py` 가 없으므로 이 단계는 필수다.**

```cmd
.venv\Scripts\pyside6-rcc resources.qrc -o resources_rc.py
```

## 6. 앱 실행

```cmd
python main.py
```

앱 창(NVM2 Application)이 뜨면 개발환경 구성 완료.
실행 로그는 루트의 `3_log\app_YYYY-MM-DD.log` 에 자동 기록된다 (30일 보존).

## 부록: 프로젝트 폴더 구조

| 경로 | 역할 |
|---|---|
| `main.py` | 앱 진입점 |
| `dll_setup.py` | ftd2xx.dll 검색 경로 등록 (개발: 루트 / 배포: exe 내장) |
| `build.bat` | 배포 빌드 스크립트 (빌드설명.md 참고) |
| `a_assets/` | 폰트·아이콘·이미지 (resources.qrc 로 exe 에 내장됨) |
| `b_core/` | 코어 로직 — a_define(상수) / b_datatype / c_manager / d_dal(통신) / e_worker_ver2(워커) |
| `c_ui/` | UI — b_control_ver2(커스텀 컨트롤) / c_window_ver2(윈도우) |
| `1_ReadMe/` | 문서 |
| `2_resource/` | 배포에 포함되는 로컬 리소스 (config / param_schema / temp / template) |
| `3_log/` | 앱 실행 로그 (자동 생성, git 제외) |
| `0_build/` | 빌드 결과물 (자동 생성, git 제외) |

폴더 경로 상수는 전부 `b_core/a_define/file_folder_path.py` 에서 관리한다.

# NVM2App 배포 빌드 가이드

배포용 exe 를 만드는 절차. 빌드는 `build.bat` 하나로 전부 자동화되어 있다.

**전제 조건**: 개발환경 구성이 완료된 상태여야 한다 (`.venv` 존재).
안 되어 있다면 [개발환경설명.md](개발환경설명.md) 를 먼저 따라 할 것.

---

## 1. 빌드 실행

프로젝트 루트에서 실행한다. 가상환경 활성화는 스크립트가 알아서 하므로
일반 프롬프트에서 실행하면 된다 (탐색기에서 더블클릭도 가능).

```cmd
.\build.bat
```

> **주의: "관리자 권한으로 실행" 금지** — 작업 디렉토리가 System32 로 바뀌어
> `.venv` 를 찾지 못하고 중단된다. 빌드에 관리자 권한은 필요 없다.

버전을 물어보면 입력한다:

```
Enter build version (e.g. 1.0.0): 1.0.0
```

> "v1.0.0" 처럼 v 를 붙여 입력해도 자동으로 제거된다.
> 버전은 빌드 중 `b_core/a_define/app_info.py` 의 APP_VERSION 에 주입되고,
> **빌드가 끝나면 원래 값으로 자동 원복**되므로 개발 트리는 변하지 않는다.

이후는 자동으로 진행된다:

| 단계 | 내용 |
|---|---|
| [1/5] | Qt 리소스 컴파일 (`resources.qrc` → `resources_rc.py`) |
| [2/5] | PyInstaller 설치 확인 (없으면 자동 설치) |
| [3/5] | 단일 exe 빌드 — `ftd2xx.dll` 을 exe 내부에 내장, 중간 산출물은 `temp_build\` (완료 후 자동 삭제) |
| [4/5] | `2_resource` 폴더를 배포 폴더에 복사 |
| [5/5] | 소스 스냅샷 생성 + `requirements_snapshot.txt` (pip freeze) 기록 |

## 2. 빌드 결과물

```
0_build\
└─ 20260806-v1.0.0\          ← [빌드날짜]-v[버전]
   ├─ NVM2App\               ← ★ 배포용 — 이 폴더를 통째로 전달하면 됨
   │  ├─ NVM2App.exe         (단일 실행 파일, ftd2xx.dll 내장)
   │  └─ 2_resource\         (config / param_schema / temp / template)
   └─ source\                ← 빌드 시점의 프로젝트 소스 스냅샷
      ├─ (전체 소스 — .git/.venv/__pycache__ 제외)
      ├─ 0_build\            (빈 폴더)
      ├─ 3_log\              (빈 폴더)
      └─ requirements_snapshot.txt  (그 시점의 패키지 버전 전체 목록)
```

- **NVM2App 폴더**: 실행에 필요한 전부. 사용자 PC 아무 위치에나 복사해서
  `NVM2App.exe` 를 실행하면 된다. 실행 로그는 exe 옆에 `3_log\` 로 자동 생성된다.
- **source 폴더**: 몇 년 후 이 버전을 다시 만들어야 할 때를 위한 스냅샷.
  이 폴더를 새 PC 에 복사하고 개발환경설명.md 절차(패키지는
  `requirements_snapshot.txt` 로 복원)를 따르면 당시 상태가 재현된다.
- `0_build` 는 릴리스가 누적된다 (같은 날짜+버전으로 다시 빌드하면 그 폴더만 덮어씀).
  git 에는 포함되지 않는다 (.gitignore).

## 3. 빌드 후 확인 체크리스트

1. `0_build\[날짜]-v[버전]\NVM2App\NVM2App.exe` 실행 → 앱 창이 뜨는가
2. 타이틀바 버전이 입력한 버전인가 (예: "NVM2 Application - v1.0.0")
3. 장비 연결 → 통신 동작 확인
4. **펌웨어 업데이트 창 열기** → ftd2xx.dll 내장이 정상인지 이 기능으로 확인된다
5. exe 옆에 `3_log\` 폴더가 생기고 로그가 기록되는가
6. 개발 트리의 `app_info.py` 버전이 원래 값으로 돌아왔는가

## 4. 문제 해결

| 증상 | 원인/조치 |
|---|---|
| 실행하자마자 깨진 문자와 함께 명령 오류가 쏟아짐 | build.bat 이 UTF-8 로 저장됨. **build.bat 은 반드시 ASCII(영문) 전용으로 유지할 것** — cmd 는 배치 파일을 CP949 로 해석한다 |
| `[ERROR] Virtual environment (.venv) not found` | 루트가 아닌 위치에서 실행했거나(관리자 실행 포함) .venv 미구성 |
| 배포 exe 에서 펌웨어 업데이트 실패 | PyInstaller 명령의 `--add-binary "...ftd2xx.dll;."` 옵션 누락 여부 확인 |
| 실패 후 app_info.py 버전이 이상함 | 실패 경로에서도 자동 원복되지만, 만약을 위해 `APP_VERSION` 값 확인 (`git diff` 로도 확인 가능) |

## 5. (참고) 스크립트 없이 수동 빌드

build.bat 을 쓸 수 없는 상황을 위한 최소 명령. 가상환경 활성화 후:

```cmd
.venv\Scripts\pyside6-rcc resources.qrc -o resources_rc.py
python -m PyInstaller --noconsole --onefile --name NVM2App --icon="a_assets\icons\nova_icon.ico" --add-binary "ftd2xx.dll;." main.py
```

결과 exe 는 `dist\` 에 생성된다. **exe 가 있는 폴더에 `2_resource` 폴더를
복사해 주어야** 실행된다. (버전 주입·스냅샷은 수동 빌드에서는 수행되지 않음)

## 6. 개발용 빌드 (exe 없이 소스로 바로 실행)

개발 중에는 배포 빌드 없이 가상환경에서 `main.py` 를 직접 실행한다.

**1) 가상환경 활성화** — 프로젝트 루트에서:

명령 프롬프트(CMD):
```cmd
.venv\Scripts\activate.bat
```

PowerShell:
```powershell
.venv\Scripts\Activate.ps1
```

> 활성화되면 프롬프트 앞에 `(.venv)` 가 표시된다.

**2) (최초 1회 또는 리소스 변경 시) Qt 리소스 컴파일**:

```cmd
.venv\Scripts\pyside6-rcc resources.qrc -o resources_rc.py
```

> `a_assets\` 의 폰트·아이콘·이미지나 `resources.qrc` 를 수정한 경우에만
> 다시 실행하면 된다. 파이썬 코드만 고쳤다면 필요 없다.

**3) 앱 실행**:

```cmd
python main.py
```

- 타이틀바 버전은 `b_core\a_define\app_info.py` 의 APP_VERSION (개발 기본값) 이 표시된다.
- 로그는 프로젝트 루트의 `3_log\` 에, 설정 파일은 `2_resource\config\` 에 기록된다.
- ftd2xx.dll 은 프로젝트 루트의 파일을 직접 사용한다 (dll_setup.py 가 경로 등록).
